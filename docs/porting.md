# 移植到其他FPGA平台：以AMD/Xilinx为例

本文是移植方案与验收清单，不代表仓库已经提供Vivado工程或完成其他器件验证。当前交付只在Efinix Ti60F225/I3上构建和烧录。先阅读[硬件结构](../hardware/README.md)，再按目标板的器件、DDR、摄像头和视频接口确定替换范围。

## 1. 先区分可复用逻辑与平台实现

| 当前部分 | 复用程度 | Xilinx侧工作 |
|---|---|---|
| 网络拓扑、整数MAC调度、残差LUT、参数分发 | 通常可保留算法和协议 | 保持位宽、取整、延迟与ready/valid；重新综合验证 |
| `cnn_dsp.v`、EFX_DSP24及其他直接DSP原语 | 必须适配 | 推断DSP或用DSP48封装实现，保持CE/复位/停顿语义 |
| `cnn_weight_ram.v`、`cnn_buffer.v`、EFX_RAM10/EFX_DPRAM10/EFX_SRL8 | 必须适配 | BRAM/XPM/分布式RAM或推断，重定端口、深宽比与读延迟 |
| 异步FIFO、视频行缓存、邮箱和复位同步器 | 协议可复用，实现需审查 | XPM或已验证自研FIFO；核对FWFT/标准读模式和复位完成 |
| 当前DDR3控制器与PHY | 整体替换 | 7系列MIG，UltraScale对应Memory IP，或Zynq PS DDR服务 |
| Sapphire CPU、Efinix JTAG、BRAM程序初始化 | 整体替换或重新封装 | 可用Zynq PS、MicroBlaze、其他CPU或主机，实现相同寄存器协议 |
| MIPI物理接口与`csi_rx_controller.sv` | 整体替换 | 目标器件支持的D-PHY/CSI-2 RX及RAW10适配层 |
| `hdmi_video_encoder.v`的编码算法 | 可作为参考复用 | 替换Ti60串行IO和差分输出；也可接外部HDMI发送器 |
| PLL、引脚、IO标准、SDC、Efinity XML | 不能直接沿用 | Clocking Wizard/MMCM/PLL、目标板XDC、Vivado工程 |
| 63296B扫描权重和3200B IN数据 | 满足同一网络与数值契约时可复用 | 容器/地址可变，内容和扫描顺序不能无验证改变 |
| 现有BIT与联合HEX | 不能复用到其他FPGA | 重新生成目标器件配置与启动包 |

更换平台不只是把`EFX_DSP24`替换为同名乘法器，也不是把SDC改后缀为XDC。板级PHY、内存控制器、CPU启动和配置Flash链路都具有器件依赖。

## 2. 第一阶段：只移植CNN核

先在Vivado建立最小工程，选择准确器件和速度等级，加入`cnn_accel/rtl`及其必要基础封装，以`cnn_core`或受控测试封装作为顶层。使用当前`CNN_STANDARD_FIRST=1`网络配置。`cnn_config.vh`含历史基础定义与条件覆盖，实际运行是55段、63296B；不能读取文件开头的24960B旧定义后直接生成权重。

测试环境通过`wt_seg/wt_shift/wt_bus`加载扫描参数，并提供完整256×144 RGB帧、gap9和相同消隐，检查输出图、每层IN样本数量及中止恢复。CPU尚未接入时可用测试平台驱动IN参数，但最终系统必须恢复后台更新；仅加载初始系数不能等价于当前历史IN推理。

可暂时关闭`USE_EFX_DSP24`、`USE_EFX_RAM10`以使用现有通用分支作仿真或资源初探；这不等于整项目已可综合：要继续搜索`EFX_`、CSI/DDR加密模块以及SRL直接实例，并替换所有被有效路径引用的厂商依赖。不要把缺失IP用常量或黑盒输出代替后当成运行成功。

## 3. DSP适配的数值与时序契约

7系列DSP48E1具有25×18乘法器和48位累加结构；不同器件的DSP能力不同，须按具体系列配置。[AMD UG479](https://docs.amd.com/api/khub/documents/gu4oRPFEh_Pm2uaAlfY6Kg/content)与[不同系列DSP说明](https://docs.amd.com/r/2024.2-English/ug440-xilinx-power-estimator/Using-the-DSP-Sheet-MULT-DSP48)可作为选型依据。

实现目标是匹配`cnn_dsp`的接口行为，而非照搬原语端口：

- 明确7位非负激活的零扩展、有符号INT8权重的符号扩展和24位结果边界。
- `LATENCY`、每一级寄存、`ce=0`时保持、`rst`与首项`first`清累加的优先级必须相同。
- 如果使用DSP内部流水后增加周期，必须同步调整valid/last/channel/客户端标签，并检查背压冻结是否覆盖全部级；不要只延长数据。
- 不把两个标量乘法随意塞进一个DSP，除非证明高低字段无交叉污染、符号修正正确且所有边界值等价。
- 再量化的23位幅值×31位乘数是另一类宽乘法，不能用一个DSP48的小乘法端口截掉高位；允许分解或推断多个DSP，但要保留完整乘积。

`cnn_requant_pipe`把移位/舍入分成两级，并在级间保留sticky信息，最后执行一次最近偶数判定；不能改成两次独立四舍五入。正负半整数、最大乘数、移位32和47、饱和边界都应逐位对照。

## 4. RAM、SRL与FIFO适配

先保持当前逻辑接口，不急于套用Ti60尾部池的物理数量。Xilinx RAMB36E1等支持多种端口宽度和WRITE_FIRST/READ_FIRST/NO_CHANGE模式，读写同址行为需要明确配置。[AMD RAMB36E1定义](https://docs.amd.com/r/2025.2-English/ug953-vivado-7series-libraries/RAMB36E1?contentId=Nm2aVbtVbH5UQNZ3PFqKqw)

为每个封装建立一张契约表：端口数和各自时钟、读出延迟、读使能撤销时的输出、写使能/半字掩码、同址冲突、初始化文件和复位行为。当前权重表存在“窄写宽读”的组合，不能按相同地址位直接接等宽RAM；地址单位是字还是字节、半字选择对应哪一侧都要校验。

使用`xpm_memory_*`或推断RAM时，明确同步读流水；环形行缓存需要保持读旧行/写新行的顺序。复位应清指针和有效位，不能为了清空逻辑把整个RAM加上不可推断的逐项异步清零。

异步FIFO的`full/empty`时序、读请求到数据的延迟以及复位后可用时刻必须匹配当前封装。选择XPM FIFO时显式决定标准读或FWFT，若有差异在适配层处理，不能让消费者读早一拍。不同域的计数只能作安全余量判断，不应当作瞬时精确占用。

Ti60的一块RAM为10240位，和RAMB18/36的资源单位不同。现有245块不能直接换算成Xilinx的245块或固定除数；要按有效容量、宽端口、银行数量、SRL/LUTRAM需求重新估计。尾部合并、两条7位通道打包等策略是否划算，要由目标器件综合结果决定。

## 5. DDR：先保持AXI128系统边界

优先让新DDR控制器对现有读写服务呈现128位、字节寻址的AXI接口。目标DDR用户端宽度若不同，可用宽度转换和跨时钟桥，而不是直接拼接现有AWLEN/ARSIZE字段。检查每拍16B、INCR突发、4KiB切分、WSTRB、ID/响应顺序以及B响应到完整帧发布的关系。

7系列MIG提供`ui_clk`及高有效`ui_clk_sync_rst`等接口，用户侧时钟与复位由生成配置决定；不能强行把所有MIG用户接口接原100MHz时钟。[AMD UG586用户接口](https://docs.amd.com/r/en-US/ug586_7Series_MIS/User-Interface?contentId=xsDUsX_pV0L9v8b8Dmd9XA) UltraScale AXI接口同样要求同步于其`ui_clk`，复位极性也应按文档处理。[AMD PG150 AXI接口](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/AXI4-Slave-Interface-Signals)

连接时等待目标IP校准/初始化完成，再允许CPU预载与图像写入。若使用Zynq PS DDR，将这些地址保留为软件与PL共同约定的保留内存区域，并处理缓存flush/invalidate、物理地址与操作系统分配问题；不要直接使用本项目0x02000000而不确认它是否被系统占用。

分开验证：数据模式读写、各类突发与背压、五槽原画保护、CNN/HDMI并发读、三槽结果发布。先证明内存内容和时序正确，再看风格效果。保持原字节顺序，尤其注意权重的小端打包与视频高位先出解包不是同一种布局。

## 6. 替代软核与启动流程

可由Zynq PS或MicroBlaze接管SPI、I2C、权重缓存和IN。APB寄存器入口可以通过AXI到APB桥保留，或改为AXI-Lite适配层；寄存器偏移、请求完成/错误和邮箱握手语义保持一致。不能将APB的可等待访问改成不确认就丢弃的脉冲写。

移植`cnn_weight_loader.c`与`cnn_in_*`时替换BSP、CLINT计时、SPI/I2C驱动和屏障。保留定长整数、64位中间运算及C整数除法/平方根规则；不要用单精度float近似后直接写系数。换CPU架构后重测正负除法、溢出边界和400个通道的更新过程。

维护100MHz计时假设：`SYSTEM_CLINT_HZ`、IN微秒计数、APB超时和摄像头延时须与新时钟一致。CPU与PL共享DDR时同步数据可见性；多字参数仍使用备用区和提交机制。

最初可用主机/JTAG将四套权重写入DDR来绕过Flash启动；随后完成独立启动链。当前HEX头部是Efinix配置格式，不能烧到Xilinx配置Flash直接启动。使用目标平台工具生成BIT/BIN/MCS或启动镜像，重新预留配置、CPU程序与权重区；若权重Flash偏移变化，同步更新CPU地址表和合并脚本。修改CRC表后必须重编译CPU，并按目标启动方式更新BRAM初始化或外部可执行文件，不能只替换权重。

## 7. 摄像头和显示接口

目标板需具备匹配摄像头电压和4-lane RAW10模式的物理接收能力。用目标D-PHY/CSI-2 RX或外部桥替换Ti60物理端口和CSI IP；将其输出适配为当前去马赛克期望的帧/行/像素有效及4像素数据格式。若输出是AXI4-Stream，要明确SOF、行尾与像素打包，并自行产生当前模块所需信号；CSI数据本身通常不能被随意反压。

检查RAW10位对齐、像素/行计数、Bayer相位、镜像/翻转和裁剪起点奇偶。当前固定白平衡适合原摄像头条件，不能用增益去补偿Bayer相位或RGB顺序错误。

HDMI可以保留当前视频扫描和TMDS编码思想，在7系列用合适的串化器/差分输出，或采用板载发送芯片。Ti60顶层对10位TMDS字取反，属于当前IO接法的一部分；移植时按新串行器、差分引脚极性逐级验证，不应无条件照搬。像素与串化时钟相位/频率、IO标准和物理走线必须符合目标实现。

先显示纯色、条纹、棋盘与像素边框，再接原画，最后接CNN。确认720p有效区、两侧布局、上下黑边、RGB通道及帧率统计，避免把显示采样错误当作网络问题。

## 8. 时钟与XDC重建

目标应尽可能保留225MHz计算域和当前gap9接口；若只能达到200MHz，按相同3683194拍计算约需18.416ms，已经超过60fps的16.667ms预算，不能直接保证60fps。若只降低时钟而不改固定除9光栅，其输出帧率也会按比例下降。提高并行度会牵涉权重读口和缓存，必须重新验证完整帧。

用Clocking Wizard/MMCM/PLL建立真实时钟关系，按新板晶振产生像素/串化时钟；不能用组合逻辑门控时钟代替使能。`VIDEO_CLK_HZ`、固定除9、分数帧尾、FPS参考时钟、按键采样与软件计时需要一起核对。

XDC应重新指定PACKAGE_PIN、IOSTANDARD、输入/输出时序、生成时钟和复位。Efinity约束里的`~FF|D`等名字不是Vivado对象路径。为同步器添加目标工具认可的ASYNC_REG属性，并检查实际放置与CDC报告。

不要把所有跨域一律`set_clock_groups -asynchronous`后就认为完成：它可能覆盖需要保持数据总线最大延迟/偏斜的约束。对握手邮箱、Gray指针分别定义同步机制和所需约束。AMD明确说明异步clock-group约束优先级高于`set_max_delay`，有最大路径延迟需求时要正确组合约束。[UG903跨域约束](https://docs.amd.com/r/2021.2-English/ug903-vivado-using-constraints/Constraining-Asynchronous-Signals)

## 9. 建议移植顺序与通过标准

1. **算术原语**：逐位验证乘法、暂停、复位、量化舍入/饱和以及所有RAM/FIFO读写时序。
2. **CNN仿真**：加载真实非稀疏权重，与独立整数参考比较，包含边界填充、残差符号、IN更新和两帧连续输入。
3. **存储子系统**：DDR校准、随机读写、视频帧池与并发服务均通过，无错误响应和越界。
4. **显示原画**：先测试图，再CSI完整帧；确认Bayer/RGB和黑边，实测采集帧率稳定。
5. **实时CNN**：实际256×144、gap9和消隐下连续运行，检查输入/结果计数、丢帧和溢出；通过布局布线setup/hold及CDC检查。
6. **IN与切换**：逐层快照样本数正确，三组轮换、系数备用区切换及快速重复风格切换无错帧/卡死。
7. **独立启动**：断电重启后CPU、摄像头、DDR和四风格正常；读取/校验Flash中的实际W与IN内容，不只验证配置文件能下载。

允许改变厂商资源映射和存储内部银行，但在声称等价前，应保持同一网络、权重扫描、数值规则和外部稀疏接口。仅综合通过、资源够用或JTAG下载成功，都不是完整移植验收。
